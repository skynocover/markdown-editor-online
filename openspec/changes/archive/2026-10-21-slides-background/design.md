## Context

Marp 的背景圖寫成 `![bg 關鍵字...](網址)`，關鍵字之間用空白隔開，不認得的字會被當成替代文字。主要的關鍵字有：
- 位置：`left`、`right`，可以加比例，例如 `left:40%`
- 大小：`cover`（預設）、`contain`、`fit`、`auto`、`50%`、`w:`、`h:`
- 濾鏡：`blur`、`brightness`、`contrast`、`drop-shadow`、`grayscale`、`hue-rotate`、`invert`、`opacity`、`saturate`、`sepia`
- 排列：同一頁連續寫好幾張會橫向並排，`vertical` 改成上下排

`slides-preview-edit` 已經提供每頁的原文範圍（`slideRanges`）和單頁工具列。

## Goals / Non-Goals

**Goals:**
- 最常用的調整（左右分割、比例、調暗、填滿方式）不用記語法
- 面板沒有的設定原樣保留，絕不因為介面沒有這個選項就把它刪掉

**Non-Goals:**
- 亮度以外的濾鏡（`blur`、`grayscale`、`contrast`、`sepia` 等），以及 `w:`、`h:`、百分比縮放：手寫的會放進 `rest` 原樣保留。模糊、黑白不做的原因：比較少用，而且 `blur` 帶單位、`grayscale` 有數值又只適合做成開關，每多一個就多一組解析規則和預設值
- 多張背景圖的排列、`vertical`
- 投影片內一般圖片（非背景）的大小調整
- 上傳圖片：這個工具不存放檔案，只能貼網址。本機路徑網頁讀不到，別人也沒有那個檔案。轉成 base64 寫進原文的話，一張壓縮過的圖約 20 萬字元，分享連結遠超過 2000 字元的提醒長度，四、五張就超過分享內容 100 萬字元的上限，對方打不開；localStorage 約 5MB 也會很快塞滿

## Decisions

### 解析成「認得的部分 + 原樣保留的部分」
`slideRanges` 用同一次 `marp.markdown.parse` 的結果，記下每頁 `meta.marpitImage.background` 為真的 image token 所在的行（`bgs`；一段文字跨好幾行時數前面的換行）。整段只有背景圖時 Marp 會把那段的 token 改成 `marpit_hidden_inline`，也要一起看。`readBackground(markdown, range)` 取第一張所在的行，再用正規表示式找出 `![bg ...](...)`。網址可以有一層成對的括號（維基百科常見），後面的 title（`"..."`）另外抓，寫回時原樣接上。
- 不直接對原文用正規表示式：程式碼區塊和行內程式碼裡的 `![bg]` 都會被誤判，範本第 3 頁就有一個寫在行內程式碼裡的示範

把方括號裡的字逐一分類：
- 認得的字轉成欄位：`side`（`left`、`right` 或空）、`width`（只寫 `left`、`right` 沒帶比例時是 Marp 預設的 50%）、`fit`（`cover`、`contain`；`fit` 視為 `contain`）、`brightness`
- 其他字依原本的順序放進 `rest`

透明度、色調也照同樣的方式：`opacity` 不帶數值是 Marp 預設的 0.5；色調只認完整的 `grayscale`、`sepia`（數值是 1），只套一半的（`sepia:0.5`）或兩個都寫時的第二個，面板表示不了，留在 `rest`。色調用一組按鈕（原色、黑白、懷舊）就能做完，不用為它多一條拉桿；模糊、色相旋轉要調數值，還是不做。

`brightness` 只寫名稱、不帶數值時，Marp 會當成 1.5（已驗證 `![bg brightness]` 會變成 `brightness(1.5)`），解析時要照這個值讀，不能當成不認得的字，否則再拉亮度會寫出 `brightness:0.5 brightness`。寫回時一律寫完整的 `brightness:數值`。寫了兩次時 Marp 會疊加（`brightness(0.3) brightness(0.8)`），面板只認最後一個，寫回時只留一個：面板自己只寫一個，手寫兩次很少見，不為它多寫解析規則。

`writeBackground` 組回 `bg` + 欄位 + `rest`，並且只輸出跟預設值不同的欄位，例如 `brightness` 是 1、`fit` 是 `cover` 時不寫。找不到 `![bg` 時回傳 null，工具列顯示成「新增」。

### 拉桿放開時才寫回
拉桿在 `change`（放開）時才寫回原文，不在 `input`（拖動中）就寫。
- 原因：每次寫回都會產生一筆復原紀錄，一邊拖一邊寫的話，Ctrl+Z 要按幾十次
- 拖動時直接改預覽畫面上這頁的樣式即時預覽：亮度、透明度換掉第一張 `figure` 的 `filter` 裡那兩個（其他濾鏡照留），寬度改這頁 section 上的 `--marpit-advanced-background-split`，以及內容那塊 foreignObject 的 `x`、`width` 屬性。放開寫回原文後預覽重新渲染，臨時樣式跟著消失
- 按住拉桿時面板淡掉只留那一條（`index.css` 的 `:has(input[type=range]:active)`），留下的那條墊白底，看得到整張投影片
- React 的 `onChange` 在拖動中就會觸發，放開要另外掛原生的 `change`
- 寫回原文會把焦點移到編輯區，拉桿失去焦點時會再觸發一次 `change`，那時還拿著舊的原文，會寫出兩個 `brightness`。拉桿記住最後寫入的值，一樣就不寫，每次渲染重設成原文的值；寫完把焦點拉回拉桿，方向鍵才能連續調

### 新增時的預設值
預設用 `![bg right:40%](網址)`，也就是範本裡示範的左文右圖。插在這頁開頭的設定註解後面。網址裡的空白和括號要編碼（`%20`、`%28`、`%29`），避免 Markdown 的圖片語法斷掉。只換這三種字元，不用 `encodeURI`：網址裡已經有的 `%20` 會被重複編碼成 `%2520`。

### 面板
沿用簡報設定面板的做法，用原生 popover：點外面、按 Esc 關閉。面板放在單頁工具列的 DOM 裡，滑鼠移進去不算離開預覽，工具列不會收起來。換到別頁時重新掛載，面板不會開著顯示另一頁的背景圖。沒有背景圖時面板是網址輸入框，下面提示「在網路上的圖片按右鍵 →『複製圖片網址』再貼上」；加入後直接換成調整面板。

### 面板排版
- 每行左邊是標籤、右邊是控制項，成組按鈕撐滿右邊、按鈕平分寬度，跟拉桿從同一條線開始，排成整齊的兩欄
- 分三組：版面（位置、寬度、填滿）、效果（亮度、透明度、色調）、圖片（網址、移除），組間用細線。多張背景圖時改用「整頁」「第一張」小標題：填滿是每張圖各自的，Marp 整頁共用的只有位置、寬度，所以「第一張」放在填滿前面，控制項的順序不變
- 亮度、透明度都用百分比顯示（亮度 0.65 顯示 65%），原文照樣寫小數
- 拉桿很難剛好停在 100%：值跟預設不同時旁邊的數字變成藍色，點一下恢復預設

### 單頁工具列
- 整份沒開頁碼時，每頁都算「沒有頁碼」，「隱藏頁碼」會一直顯示成已開啟。改成：這頁不寫 `_paginate` 時本來就沒頁碼的話停用，提示到「簡報設定」打開；這頁寫了 `_paginate: false` 的話照樣可以取消
- 「背景圖」會展開面板，不是開關：前後加分隔線、後面加 ▾，有沒有背景圖都不變色
- 只放圖示，用途看提示（提示先說按鈕名稱，例如「深色：這頁改成深色」；不寫 `_class: invert` 這類語法，大多數人不打算學 Marp，按下去左邊原文也看得到改了哪一行）：工具列滑過每一頁都會出現，寬度從約 450px 縮到約 230px，窄預覽也放得下，不用再判斷寬度切換。代價是觸控裝置看不到提示，按了才知道，靠 Ctrl+Z 還原。lucide 沒有「隱藏頁碼」，用 # 加一條斜線
- 開關也有圖示，開啟時藍底，跟動作按鈕一致
- 工具列跨在投影片的上邊框（垂直置中在邊框上），少擋一半投影片；「背景圖」面板打開時，按鈕的提示用 CSS 藏起來，不然會壓在面板底下

### 移除背景圖
刪掉那個圖片語法所在的整行；如果那一行還有其他文字，就只刪圖片語法本身。

## Risks / Trade-offs

- [使用者手寫的替代文字跟關鍵字混在一起] → 不認得的字一律保留在 `rest`，順序不變
- [同一頁有多張背景圖] → Marp 的左右分割是整頁共用的：任何一張寫了 `left`、`right`，所有背景圖都擠進同一區並排。面板分成「整頁」（位置、寬度）和「第一張」（其他），註明幾張會並排，不讓人以為只動了第一張。Marp 以最後一張寫了 `left`、`right` 的為準（後面只寫 `right` 沒帶比例的，沿用前面寫的比例），所以位置、寬度每張都要看；寫回時只寫在第一張，其他張的 `left`、`right` 拿掉，不然會被後面的蓋掉
