## Context

`parseMarkdown` 現在是 `DOMPurify.sanitize(marked.parse(md, { breaks: true }), { FORBID_TAGS: ["style"] })`，在 `render()` 裡同步呼叫，外層用 `useMemo` 快取。一般文件、唯讀分享預覽、字數計算都走這一條。簡報走 Marp（markdown-it），是另外一條路。

marked 的表格 token：`{ type: "table", header: Cell[], rows: Cell[][] }`，每個 `Cell` 有 `text`（原始 Markdown）和 `tokens`（inline tokens）。實測：`=A2+1` → `text: "=A2+1"`；`` `=A1` `` → `text: "`=A1`"`；`\=x` → `text: "\\=x"`。所以只要看 `text` 就能判斷是不是公式，行內程式碼和跳脫也自然被排除。

分享連結是不受信任的輸入：任何人都能做一個連結，讓別人打開時執行裡面的公式。

## Goals / Non-Goals

**Goals:**
- 預覽時計算，原文、存檔、分享內容完全不變
- 公式來自不受信任的分享連結也安全：不執行任意程式碼，不會讓頁面卡死
- 錯誤只影響那一格，不會讓整份預覽壞掉

**Non-Goals:**
- 跨表格參照或命名範圍
- 字串運算、日期、`IF` 等邏輯函數（之後有真實需求再加）
- 數字格式設定（貨幣、固定小數位數）：結果一律加千分位，見「輸出格式」
- 貨幣符號的數字辨識（`$30`、`NT$30`）：結果帶不回符號，單位寫在表頭比較乾淨
- 簡報（Marp）裡的表格：Marp 用 markdown-it，要另外接，工作量大約多三成；簡報裡的表格通常是已經算好的結果，等有需求再做
- 在編輯區顯示計算結果或自動完成

## Decisions

### 掛在 marked 的 lexer 和 parser 中間
`parseMarkdown` 改成：`tokens = marked.lexer(md, opts)` → 找出所有 `table` token（包含 blockquote、list 裡的巢狀 token，用 `marked.walkTokens`）→ 計算 → `marked.parser(tokens, opts)` → DOMPurify。
- `opts` 必須是 `{ ...marked.defaults, breaks: true }`：`marked.lexer(md, { breaks: true })` 會取代預設選項，`gfm` 跟著不見，表格會被解析成段落（已實測）。`lexer` 和 `parser` 都傳同一個 `opts`
- 替代方案：渲染後用 DOM 處理 HTML 表格。不採用：還要再解析一次 HTML，而且原始的 `\=` 和行內程式碼資訊已經不見了
- 替代方案：寫成 marked extension（`marked.use`）。不採用：會改到全域的 marked 實例，影響範圍不好控制；目前只有一個呼叫點，直接寫比較清楚

### 計算結果寫回 token
公式儲存格的 `tokens` 換成一個 `text` token（內容是結果字串）。結果只會是數字或固定的錯誤字串，沒有注入的問題；最後仍會經過 DOMPurify。不做滑鼠移上去顯示公式（`title`），因為要寫自訂的 renderer，而點進原文就能看到公式。

### 座標規則
- 欄：由左到右 A、B、C…（只支援 A–Z，表格超過 26 欄的情況不處理）
- 列：表頭是第 1 列，第一筆資料是第 2 列，跟從試算表貼上時的位置一致
- 參照不分大小寫：`b2` 等同 `B2`
- 表頭的公式也會計算：表頭和資料列一樣處理，不用多寫特例
- 單一參照超出表格 → `#REF`；範圍超出表格時截到表格邊界（`SUM(B2:B100)` 可以替之後新增的列預留空間，跟 Excel 的習慣一致），整個範圍都在表格外才是 `#REF`

### 自己寫遞迴下降解析器，不用 eval
文法：
```
expr   := term (('+'|'-') term)*
term   := unary (('*'|'/') unary)*
unary  := '-' unary | primary
primary:= NUMBER | REF | FUNC '(' args ')' | '(' expr ')'
args   := arg (',' arg)*        arg := RANGE | expr
```
先切 token 再解析，大約一兩百行。`eval` 或 `new Function` 會讓分享連結變成可以執行任意程式的入口，DOMPurify 也擋不住，所以完全不考慮。也不加 mathjs 這類套件，因為需要的功能很少。

### 儲存格的值
- 一般儲存格：去掉前後空白後，符合 `^-?(\d{1,3}(,\d{3})+|\d+)(\.\d+)?%?$` 才算數字（`1,200` → 1200）；結尾是 `%` 時除以 100（`5%` → 0.05）；空白算空值；其他是文字（包含 `$30`）
  - 用 regex 而不是「去掉逗號再 `Number()`」：後者會把 `1,2,3` 當成 123，也會接受 `0x1F`、`1e3`
- 四則運算中：空值當 0；文字 → `#ERR`
- 公式的結果一定是數字：`=A1` 參照到文字格也是 `#ERR`，不顯示那段文字，輸出格式就只有一種
- 函數的範圍參數：略過空值和文字（跟 Excel 一樣），`COUNT` 只算數字；範圍裡有錯誤值時傳遞錯誤，不略過
- 錯誤會往外傳遞：參照到錯誤的儲存格，結果就是那個錯誤

### 錯誤值只有三種：`#ERR`、`#REF`、`#CYCLE`
`#REF` 和 `#CYCLE` 告訴使用者該修哪裡，值得分開；其他都是 `#ERR`。
- 不另外做 `#DIV/0`：每個公式算完統一檢查 `Number.isFinite`，不是就 `#ERR`。除以零（`Infinity`）、空範圍的 `AVG`（`NaN`）、`MIN`/`MAX`（`Math.min()` 是 `Infinity`）、溢位，一個檢查全部處理，不會顯示 `∞`

### 公式參照公式：記憶化加上「計算中」集合
每格最多算一次（memo）；開始計算某格前先放進 visiting 集合，遞迴時如果又遇到它就回傳 `#CYCLE`。memo 不能省：每格都參照前一格兩次的話，沒有 memo 計算量會呈指數成長。
- 計算量大約是「公式數 × 範圍大小」：每個 `SUM` 都會重新掃一次範圍。1000 列、每列都 `SUM` 一整欄，大約是 1M 次運算，還可以接受；但每一格都 `SUM` 一大塊範圍時會到數億次，所以讀格子的次數設上限，見下一節

### 輸出格式：一律加千分位
用 `new Intl.NumberFormat("en-US", { maximumFractionDigits: 2, signDisplay: "negative" })`：`20500` → `20,500`，`1000/3` → `333.33`，`0.1+0.2` → `0.3`（順便消掉浮點誤差）。
- 為什麼最多 2 位：表格大多是金額，台幣是整數、外幣到分；10 位會出現 `333.3333333333`。只影響顯示，參照時用完整精度，跟 Excel 一樣
- 不補 0（`2.5` 不寫成 `2.50`）：台幣表格不會到處都是 `.00`
- `signDisplay: "negative"`：`-0.001` 四捨五入後顯示 `0`，不是 `-0`
- 代價：很小的數字（匯率 `0.0032`）顯示成 `0`；各格各自四捨五入，加總看起來可能差 0.01
- 為什麼加千分位：輸入的 `12,000` 能當數字，輸出卻是 `20500`，同一欄格式不一致，看起來像 bug；這類表格大多是金額
- 固定用 `en-US`：不跟著瀏覽器語系走，不然德文語系會變成 `20.500`，跟輸入的千分位規則不一致
- 代價：算出年份這類數字也會加逗號（`2,026`），可以接受

### 防止頁面卡死：每個表格包一層 try/catch
括號巢狀太深、跨儲存格的參照鏈太長（A2 → A3 → … → A10000）都會遞迴到堆疊溢位。每個表格的 `evaluateTable` 外面包一層 try/catch：丟出例外時，該表格照原文顯示，其他表格和預覽不受影響。
- 不另外限制括號深度：try/catch 已經接得住，只差在整個表格照原文顯示、而不是單格 `#ERR`；這種公式只會出現在惡意連結裡
- 不限制公式長度：`a+b+c+…` 用迴圈解析，不是遞迴，再長也只是線性時間
- 範圍會截到表格邊界，所以 `SUM(A1:Z99999)` 的實際成本受表格本身的大小限制
- 讀格子的次數上限 1000 萬次（大約 0.2 秒），整份文件共用（每個表格各自計算的話，放很多個表格就能繞過），超過就丟出例外，之後的表格照原文顯示：範圍截到表格邊界還不夠，1000×26 的表格每格都 `SUM` 上面所有列，壓縮後只有幾 KB 的分享連結就能讓對方卡住好幾秒

## Risks / Trade-offs

- [`useMemo` 每次打字都重算整份文件的所有公式] → 一般表格只有幾十格，可以忽略；真的遇到很大的表格再考慮只重算有變動的表格
- [使用者以為這是 Excel，期待更多函數] → README 列出支援的範圍；超出範圍的就該用試算表
- [有人本來就在表格裡寫 `=` 開頭的文字（例如 `=>`）] → 會被當成公式算成 `#ERR`；用 `\=` 跳脫。這是行為改變，但這種內容很少見，原文也不會被改掉，所以不加 `calc: true` 之類的開關（多一道門檻，跟「打 `=` 就能算」的直覺衝突）
- [從 Excel 貼上的金額帶貨幣符號（`$30`），參與運算變成 `#ERR`] → README 說明單位要寫在表頭
- [簡報裡寫 `=SUM(...)` 會原樣顯示] → 第一版明確不支援，README 註明
- [欄、列號在 Markdown 原文裡看不到] → 第一版不處理；之後可以考慮在預覽表格邊緣顯示 A/B/C、1/2/3
- [唯讀分享連結的對方看到計算結果，但原文才是真正的內容] → 結果是確定的，同一份原文在任何人那邊都算出一樣的值
