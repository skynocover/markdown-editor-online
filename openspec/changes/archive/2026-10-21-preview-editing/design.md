## Context

預覽是 `marked` 產生的 HTML，經 DOMPurify 過濾後用 `dangerouslySetInnerHTML` 放進頁面。原文是唯一的資料來源，預覽每次都從原文重新產生。

## Goals / Non-Goals

**Goals:**
- 在預覽做的修改一律寫回原文，原文仍是唯一的資料來源
- 每次修改都能用 Ctrl+Z 還原
- 對不上原文位置的元素不能編輯，絕不寫錯位置

**Non-Goals:**
- 引用、清單裡的表格不能編輯（位置難算，也很少見）
- 在表格中間插入列或欄（目前只能加在最後面，再用拖曳移動）
- 公式參照的格子著色、資料夾本身換順序

## Decisions

### 用 token 的 raw 長度找回原文位置
頂層 token 的 `raw` 依序串起來就是原文，所以累加長度就能算出每個表格的起點（`markTables`），再用 renderer 寫進 `data-start`。checkbox 則是在每個頂層區塊裡，用 regex 找出原文的 `[ ]`，跟 checkbox token 依序配對（`markTasks`）。數量對不上時（例如清單裡的程式碼區塊也有 `- [ ]`），整個區塊都不記位置，checkbox 會停用。
- 寫回之前會再確認位置上確實是 `[ ]` 或 `[x]`：重複的連結定義會讓 marked 丟掉 raw，位置可能算偏
- 不採用 DOM 反查文字：同樣的文字可能出現很多次，沒辦法確定是哪一個

### 寫回用 execCommand("insertText")
先選取原文要取代的範圍，再插入新文字，這樣修改會進入瀏覽器的復原紀錄，Ctrl+Z 可以還原。不支援時改用 `setState`。

### 表格整個重寫
編輯一格時讀出整個表格（`readTable`），改完用 `writeTable` 重新產生整段 Markdown 寫回去，不去算每一格在原文的位置。
- 代價：第一次寫回時，表格會重新排版
- 有任何一列的格數比表頭多時不給編輯：marked 會把多出來的格子丟掉，寫回去就不見了
- `|` 寫回時要跳脫，已經跳脫過的不重複加

### 換格和插入座標在 mousedown 處理
等到 click 觸發時，預覽已經因為寫回而重畫，瀏覽器不會送出 click，所以換格和插入座標都放在 mousedown 處理。`Preview` 的 `{__html}` 用 `useMemo` 記住，避免每次 render 都重設 innerHTML，把正在編輯的格子洗掉。

### 刪除、移動欄列時更新公式座標
用新舊索引的對照表（order）改寫公式裡的 A1 座標。被刪掉的單一參照變成 `#REF`。範圍的端點被刪掉時往內縮，整個範圍都被刪掉才是 `#REF`。表格外的座標照刪掉的數量往前移，跟試算表的行為一樣。

### 快捷鍵
Mac 只認 Cmd，因為 Ctrl+B 是系統的游標左移。選取範圍前後的空白不包進去。在粗體裡選字按斜體會變成 `***粗斜體***`，不會把粗體拆掉。

### 側邊欄順序就是 files 陣列的順序
拖到某個檔案上，就插到它前面，並搬進它所在的資料夾；拖到資料夾上，就放到該資料夾的最後面。不另外存排序欄位。

## Risks / Trade-offs

- [第一次編輯會重新排版整個表格] → 只有排版改變，內容不變
- [表格內的文字無法拖曳反白] → mousedown 用來換格和選範圍；要複製文字可以到原文操作
- [唯讀預覽也會用到同一個 renderer] → 用 CSS 讓 checkbox 不能點，表格不掛事件
